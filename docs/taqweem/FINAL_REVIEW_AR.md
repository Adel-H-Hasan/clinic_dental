# نسخة المراجعة النهائية — ليست اعتماداً للإنتاج

تستكمل هذه الوثيقة التقرير السابق. المشروع الأصلي والفرع feature/taqweem-full-frontend محفوظان؛ لا دمج في main. حُفظت الواجهات والأصول والأدوات والتوثيق في التزام مستقل، بينما بقيت تغييرات الخلفية الأربعة خارج الالتزام ومعلّقة للموافقة. نسخة ZIP تحتوي الحالة الحالية بما فيها تلك التغييرات، كي يمكن اختبار الربط؛ وجودها في الأرشيف لا يعني اعتمادها.

## التنقل المنفذ

الشريط يعرض الرئيسية وأطباءنا والخدمات ورحلة الرعاية واللغة والحجز. تعرض جلسة الزائر الدخول والتسجيل، وتعرض الجلسة المصادق عليها لوحة دور المستخدم والخروج بنموذج POST محمي بـCSRF. تنتقل الروابط الثانوية إلى قائمة الجوال دون تغيير محركات الحركة أو الفيديوهات أو النموذج. شعار كل لوحة يعيد إلى الرئيسية.

الأطباء والخدمات مرتبطون بدليل Laravel الفعلي، والخدمات المعروضة تخص الأطباء الموجودين في صفحة نتائج الدليل الحالية؛ لا يوجد كتالوج مصطنع. زر الحجز يطلب المصادقة من الزائر ثم يعيده إلى الحجز، والمريض يدخل الحجز مباشرة. الطبيب والمدير يُوجهان إلى مساحة دورهما. لا يُسمح لهما بالحجز كأنهما مرضى.

- أعيدت رحلة التسجيل والتحقق والدخول والحجز وتأكيد الطبيب ورؤية الحالة للمريض على الواجهة المحدثة: 35 نقطة تحقق إنجليزية و36 عربية ناجحة. بيانات الاختبار في قاعدة مستقلة.

- php artisan view:cache ناجح، وفحوص صياغة القوالب المعدلة ناجحة. npm run build ناجح: 61 وحدة. احتاج البناء صلاحية قراءة خارج قيود العزل لتشغيل esbuild.

- git diff --check ناجح. الفروق الخلفية الحالية مطابقة لنقطة التجميد السابقة. لا تغييرات على النماذج أو الحجز أو السياسات أو الوسائط أو المخطط أو إعدادات الإنتاج.

الأدلة واللقطات المختارة في output/qa-evidence داخل ZIP. توجد اختبارات أوسع موثقة في DELIVERY_AR.md؛ فحص الاستجابة الـ216 سابق لتعديل الشريط، ويكمّله فحص التنقل الجديد ولا يُقدّم كتجربة جديدة لكل شاشة.

## تشغيل ZIP على نسخة جديدة فقط

1. فك الضغط في مجلد جديد، دون الكتابة فوق مشروع الفريق. شغّل MySQL من XAMPP وثبّت PHP 8.2+ وComposer وNode.
2. افتح PowerShell داخل clinic_dental المستخرج، ثم:

```powershell
Copy-Item .env.example .env
composer install
php artisan key:generate
npm.cmd ci
npm.cmd run build
```

3. عدّل .env محلياً لقاعدة جديدة وفارغة اسمها taqweem_review وبيانات اتصال XAMPP. أنشئ هذه القاعدة عبر phpMyAdmin. بعد التأكد أنها ليست قاعدة الفريق:

```powershell
php artisan migrate
php artisan serve
```

لا تستخدم migrate:fresh ولا تستبدل مفاتيح أو إعدادات مشروع قائم. البريد الافتراضي log وخدمات AI غير مهيأة، ويُضبط البريد والخدمات بعد المراجعة.

## تجربة الأدوار ببيانات معزولة

لإنشاء حسابات عرض آمنة دون استخدام قاعدة الفريق، اتبع RUN_DEMO_AR.md: شغّل php tools/qa-setup.php مرة واحدة، ثم php -S 127.0.0.1:8097 -t public tools/qa-router.php. الأداة تنشئ قاعدة QA جديدة عشوائية وكلمة سر محلية عشوائية. لم تُضمّن ملفات runtime أو جلسات أو كلمات سر في ZIP. على نسخة ZIP يجب إنشاء تلك البيئة من جديد قبل الاختبارات.

الطبيب doctor@taqweem.test والمدير admin@taqweem.test؛ كلمة السر المولّدة تُقرأ محلياً من output/qa-local/runtime.json. سجّل مريضاً من الرئيسية وافتح رابط التحقق من سجل البريد في output/qa-local/application.log. ادخل المريض، اختر الطبيب والخدمة والوقت، احجز؛ ثم ادخل الطبيب وأكّد الموعد، وعد للمريض لرؤية الحالة. افتح المدير في جلسة جديدة لتجنب مشكلة intended الأصلية الموثقة.

## حدود التسليم وموافقة الخلفية

الواجهات والرحلة السابقة مكتملة ضمن الوظائف الحالية التي اختُبرت. لم يُختبر توليد AI فعلي أو تسليم بريد خارجي، ولم تُضف إجازات أو مفضلة أو إعدادات لا يدعمها الخادم. لا يشمل هذا قبولاً سريرياً أو تدقيق وصول شاملاً أو كل المتصفحات. مشكلة إعادة توجيه المدير إلى رابط مريض سابق ما زالت قائمة في حالة الجلسة المذكورة.

الفروق الحرفية وأثر الملفات الأربعة في BACKEND_REVIEW_AR.md. ضرورتها واقتراح إصلاح إعادة التوجيه في REDIRECT_PROPOSAL_AR.md؛ الاقتراح غير مطبق ويحتاج موافقة منفصلة.
