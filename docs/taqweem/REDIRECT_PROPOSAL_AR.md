# اقتراح توجيه الدخول — غير مطبّق

الموضع: app/Http/Controllers/AuthController.php، الدالة login، السطر الذي يستدعي redirect()->intended($fallback).

المشكلة: يحفظ Laravel رابطاً محمياً طلبه الضيف. إذا كان الرابط للمريض ثم دخل الشخص بحساب مدير، يُعاد إلى رابط المريض فترد طبقة الصلاحيات بـ403. الحماية تعمل، لكن وجهة الدخول غير مناسبة. هذه المشكلة موجودة في السلوك الأصلي، ولم تُغيّر صلاحيات لتجاوزها.

الحل المقترح المحدود: إبقاء intended للمريض حتى تبقى رحلة الحجز بعد المصادقة، وتوجيه الطبيب والمدير دائماً إلى لوحة دورهما مع إزالة الوجهة القديمة من الجلسة. لا تغيير في التحقق من كلمة السر أو البريد أو الأدوار أو الحجز. لا يُطبّق هذا الاقتراح قبل موافقة مستقلة.

```diff
--- a/app/Http/Controllers/AuthController.php
+++ b/app/Http/Controllers/AuthController.php
@@
-        return redirect()->intended($fallback);
+        if (in_array($request->user()->role, ['doctor', 'admin'], true)) {
+            $request->session()->forget('url.intended');
+            return redirect()->to($fallback);
+        }
+        return redirect()->intended($fallback);
```

الأثر المقصود والمخاطر: لن يعود الطبيب أو المدير تلقائياً إلى رابط عميق سابق بعد الدخول، بل إلى لوحته. هذا تنازل مقصود مقابل توجيه ثابت؛ إذا كان الرجوع إلى الروابط العميقة مطلوباً، يلزم تصميم قائمة سماح للمسارات بحسب الدور بدلاً من هذا الحل المحدود. اقتراح المريض لا يغير سلوكه الأصلي.

التحقق المطلوب بعد الموافقة: ضيف يطلب /patient/booking ثم يدخل مديراً أو طبيباً فيرى اللوحة المناسبة؛ مريض يعود إلى الحجز مع service وdate؛ دخول عادي لكل دور؛ إعادة رفض المسارات المخالفة بـ403؛ استمرار اللغة والخروج. لم تُنفّذ اختبارات هذه الرقعة لأنها غير مطبّقة.

ضرورة التغييرات الأربعة السابقة: AuthController ضروري لوجهة لوحة المريض الافتراضية وحفظ اللغة بعد الخروج؛ DoctorProfileController تصحيح ملكية الملف المعروض للتحرير ولا يخص تجميل الواجهة؛ routes/web.php ضروري لربط الرئيسية والشاشات واللغة؛ WorkspaceController مطلوب لعرض البيانات دون استبدال متحكمات الكتابة الأصلية. يمكن رفض أي منها، لكن الواجهات المعتمدة عليها تحتاج حينها إعادة تحديد نطاق؛ لا يُحذف أي عمل تلقائياً.
