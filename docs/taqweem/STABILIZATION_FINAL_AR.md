## المشاكل والإصلاحات

1. **تجمّد الدخول السينمائي:** أثبت Chrome تحميل الملف بالكامل مع نطاق `seekable` صفري على الخادم المحلي؛ يعود الانتقال إلى أول إطار. أضيف كشف الحالة وتحويل البايتات الأصلية إلى Blob قابل للانتقال. لم تُستبدل الفيديوهات. ثُبتت الأحداث قبل التحميل، ومُنعت طلبات الانتقال المتداخلة، وأُصلح الملصق عند التعذر وReduced Motion. المشهد يستخدم `requestAnimationFrame` أصلاً، وليس GSAP/ScrollTrigger؛ لم نضف مشغلاً منافساً.
2. **قياسات المصادقة:** قواعد CSS العامة كانت تتغلب على قياسات الحقول وصورة العمود الجانبي. صُحّحت أولوية المحددات وأُزيل عنوان ثانوي زائد، مع إبقاء التمرير الطبيعي والحقول والمسارات وCSRF، وخطي Cairo وInter واتجاهي RTL/LTR.
3. **تكرار الأخطاء والعناوين:** مكوّن مساحة العمل يعرض ملخص الأخطاء ثم تعيد قوالب النظام عرضها. أُزيل التكرار من الإدارة والملفات الشخصية والخدمات والجداول والملاحظات والتقارير وSmile AI، وأُزيل عنوان Smile AI المكرر.
4. **نصوص قديمة:** صُحّح وصف الرئيسية والنص الذي يؤجل ملفات الأطباء إلى ما بعد الربط. أُزيل إرشاد المستخدم إلى سجل يحتوي روابط تحقق حساسة. بقي السرد السينمائي والبوابة ثلاثية الأبعاد.
5. **إعادة التحقق:** المستمع وحدث التسجيل يعملان في الاختبارات. أُضيفت إعادة إرسال محدودة المعدل، ورسائل عربية وإنجليزية، ومعالجة فشل الإرسال دون فقد الحساب أو كشف تفاصيل النقل. بقي توقيع Laravel وانتهاء الرابط كما هما.
6. **وجهة الدخول:** كان `intended` يسمح بالعودة إلى صفحة محفوظة لدور آخر. أصبح التحويل إلى لوحة الدور مع الحفاظ على الحجز من نفس الدور والأصل. أُضيف تحويل صحيح للمستخدم المسجل عند فتح صفحة ضيف، وأصبحت صفحة التحقق متاحة دون حلقة تحويل.
7. **تغيير البريد:** كان البريد الجديد يحتفظ بتأكيد القديم. أصبح تغيير البريد يلغي تأكيده ويرسل تحققاً جديداً، ويرفض رابط البريد السابق.

طُبّق `BACKEND_PENDING.diff` بعد الموافقة الأولى، و`PROFILE_VERIFICATION_PENDING.diff` بعد الموافقة الثانية. الأسماء محفوظة كسجل للمقترحات؛ لا توجد رقعة منهما تنتظر الموافقة الآن.

- بحسب المراجعة الثابتة، تعطيل الحساب يمنع تسجيل الدخول اللاحق، لكنه لا يسحب جلسة مسجلة مسبقاً عبر Middleware الأدوار. بقي هذا السلوك دون تغيير؛ تغييره يحتاج اعتماد تعديل صلاحيات إضافي.
- إدارة الوصول تعتمد حالة المستخدم والأدوار الحالية. لم تُنشأ شاشة أو وظيفة مستقلة لا يدعمها Backend.

## التشغيل المحلي

خادم QA الحالي يعمل على `http://127.0.0.1:8199`. رابط التحقق المرسل يخص قاعدة QA ويتطلب فتحه على الجهاز نفسه أثناء عمل الخادم. لا يمثل نشراً على الإنترنت.

لإعادة تشغيل الخادم بعد إيقافه، من مجلد المشروع:

```powershell
php -S 127.0.0.1:8199 -t public tools/qa-router.php
```

بيئة QA موجودة بالفعل؛ لا تعِد إنشاءها فوق الحالية. أوامر التحقق:

```powershell
php vendor/bin/phpunit --no-progress
php artisan view:cache
npm.cmd run build -- --configLoader runner
node tools/qa-entrance.mjs
node tools/qa-auth-layout.mjs
node tools/qa-navigation.mjs
```

اختبارات المتصفح تتطلب Chrome وخادم QA. إعادة رحلة الحجز تنشئ بيانات اصطناعية إضافية في قاعدة QA فقط. لا تعِد تشغيل أداة SMTP؛ التجربة الواحدة المصرح بها سُجلت بالفعل.
